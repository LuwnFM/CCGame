# Firewell CCG — закрытая PvP-альфа

Основа: актуальные [решения автора](docs/decisions-v0.9.13.md). Игровой сервер хранит состояние и профили в SQLite; клиент — статические файлы из `web/`. Шесть стартовых колод, редактор, очередь, чат и доска доступны локально.

## Локальный запуск

Нужен Node.js 24+. В папке репозитория откройте **`start-firewell.cmd`** на Windows или `bash start-firewell.sh` на Linux/macOS. Скрипт спрашивает общий пароль доступа к альфе (не менее 10 символов), создаёт папку `data/`, запускает сервер и SQLite по адресу `http://localhost:3000`. Для тестирования: `npm test`. Запуска без установки npm-пакетов достаточно.

Для телефона в той же локальной сети ответьте «y» в скрипте и откройте `http://IP-КОМПЬЮТЕРА:3000` на телефоне. При необходимости разрешите входящие подключения для Node.js в локальной сети. У разных игроков собственные пароли профиля; общий пароль нужен только для регистрации. Логин (3–20 латинских букв/цифр/подчёркиваний) уникален без учёта регистра; ID остаётся прежним при смене логина. Профиль можно удалить после ввода личного пароля. База `data/firewell.sqlite` — единственная постоянная база; делайте резервную копию после остановки сервера.

### Клиент на Vercel

`vercel.json` публикует только статическую папку `web/`. На первом экране Vercel-клиента игрок вводит **публичный HTTPS-адрес** игрового сервера. Сервер на `localhost` не доступен посетителям Vercel: нужен ваш HTTPS-туннель или прокси к компьютеру, где запущен Node.js. В скрипте запуска укажите точный адрес Vercel-клиента (например, `https://ccgame-omega.vercel.app`) для CORS. Пароли, профили, SQLite, подбор и матч остаются на компьютере; Vercel не хранит их. Сеансы клиента привязаны к браузеру, а команду можно продолжить с другого устройства после входа в профиль.

## Что можно сыграть

- Два игрока по 40 HP; 70 карт, 26 Владений, начальная рука из семи и один выборочный муллиган. Гарантия базового цветного Владения применяется сервером.
- Цветная и нейтральная Энергия, оплата, одно Владение за ход, основное поле из восьми мест и вспомогательное из четырёх. Первый игрок не добирает на первом ходе, пустая колода не наносит урона, в конце хода рука сбрасывается до восьми.
- Атака по Владетелю, видимому Существу и Легенде, добровольный перехват, Страж, Полёт, Щит, Первый удар, Пробивание, Похищение жизни, Натиск, Напор на Существо, дополнительная атака, Скрытность и Отрава от попадания.
- Легенды с отдельной зоной и Лояльностью, уникальные предметы во вспомогательной зоне, фиолетовая Техника с Ритуалом Жертвы и пятью вариантами награды. Ритуальные награды и созданные токены стираются вместо Сброса.
- Серверная ревизия и ключи идемпотентности, закрытая рука соперника, SQLite, таймеры и автоматический допустимый ответ. Бюджет обязательных эффектов откатывает команду и ставит матч на паузу при превышении.
- Профили с солью и `scrypt` для личного пароля, постоянным UUID и сменяемым логином; до десяти собственных колод из общего каталога; очередь подбора с присутствием за последнюю минуту, чат с логином/ID, жалобы и предложения в SQLite. Ручная комната по коду остаётся для тестов.

## Колоды и развитие

В каждой 26 Владений, 18 ванильных существ (25,7%), две Легенды и один уникальный предмет. Остальные места занимают существа с эффектами; у Искажения ещё три ритуальные Техники. См. [состав и лор](docs/decks-and-lore.md) и [реестр механик](docs/mechanics.md).

В текущем срезе отсутствуют адресные Техники вне Ритуала, Предвидение, Отклик Владения, Оберег, Очищение, Немота, Сковывание, Детонация и Рикошет. Упомянутые операции не назначены картам стартового каталога. Публичный HTTPS-сервер, мониторинг и модерация чата требуют отдельной инфраструктуры. Не учитывайте неработающие эффекты при балансировке.

## Актуализация 21.10.2026 — рейтинг, матчмейкинг и история

- В лобби появляется рейтинг **топ-10 по победам**: имя и неизменяемый UUID, число побед. Он использует таблицу `match_history`, принимает только законченные победой игры (`winner=0/1`), не считает ничьи/паузы. На сервере кешируется на **10 минут**, после смены логина победы остаются с ID.
- Упрощённая очередь PvP берёт другого активного игрока с ожидающей колодой, использует SQLite-транзакцию, исключает собственный ID, сохраняет комнату. Отдельные тесты проверяют повторную постановку, разные колоды и устаревшие очереди. До релиза нужны реальные тесты двух пользователей вне LAN.
- Постоянный аккаунт: латинский логин `[A-Za-z0-9_]{3,20}`, пароль профиля 10–128 символов с буквой и цифрой; соль + `scrypt`. UUID остаётся при смене ника. Действительная сессия восстанавливается после обновления браузера; другой браузер может войти логином и паролем. Общий альфа-пароль применяется **только к регистрации**, читается из **серверной переменной окружения** `FIREWELL_ALPHA_PASSWORD`, никогда из Vercel-клиента. Для текущего тестирования вводится согласованное в чате значение, без коммита его в репозиторий; при внешнем публичном запуске пароль нужно заменить.
- Чат сохраняет всю историю в SQLite, постранично показывает старые сообщения, повторная отправка не ранее 5 секунд и в интерфейсе, и на сервере. Баг-репорты, проблемы и предложения хранятся с номером, заголовком, описанием, категорией, опциональным кодом матча, UUID, временем и статусом; автор видит только свои.
- Команды матчей и тайм-аутов журналируются в `match_events`; по завершении создаётся защищённый файл `data/match-archives/<room>-<timestamp>.json.gz` и SHA-256. Архив содержит полное состояние матча с **обеими скрытыми руками**: не публикуйте его игрокам или на Vercel.
- Административный локальный экспорт: `node scripts/export-support.mjs ./data/firewell.sqlite ./admin-exports` (файлы `reports.jsonl`, `chat.jsonl`). Локальный анализ матчей: `node scripts/analyze-matches.mjs ./data/match-archives`. Файлы экспорта, БД, архивы и резервные копии строго вне статического хостинга.
- Отдельная вкладка правил доступна по-русски и по-английски; русский остаётся основным языком.
- Нейтральный Свирус Жирникус заменяет «Ветерана новых хранителей» **без изменения стоимости, числа копий и боевых параметров**. 50 новых небазовых Владений (10 каждого цвета) добавлены только в общий каталог.
- Для игры с другой сети компьютерному Node.js потребуется стабильный **публичный HTTPS-прокси или туннель**. Vercel предоставляет только статический клиент; `FIREWELL_CLIENT_ORIGIN` на сервере должен точно совпадать с адресом клиента. Работа из РФ/VPN не доказывается локальным тестом: нужны проверки реального DNS, доступа, задержек и переподключений.
- **На Vercel не делать автоматических или промежуточных деплоев**; единственная публикация после приёмки P0/P1 и настоящей сетевой проверки. Новый план: [alpha-roadmap.md](docs/alpha-roadmap.md).

### Баланс и ограничения текущих результатов

Каждый стартовый набор по-прежнему **70 карт: 26 базовых Владений, 18 Существ без эффектов, 2 Легенды, 1 уникальный предмет**, плюс либо 23 Существа с особенностями, либо 20 и 3 ритуальные Техники у Искажения. 50 новых земель и новые названия не вставлены в стартовые колоды. 288 автоматических матчей проверяют целостность и работу механик, **не достаточны для доказательства соревновательного баланса**. Также требуется более полная проверка английского текста и браузеров вне Chromium.

## Локальный тестовый релиз с чистыми аккаунтами и статистикой (Windows)

1. Скачайте ZIP ветки `main` с GitHub и распакуйте его в **новую папку**.
2. Установите Node.js **24+**. Для обычного запуска используйте `start-firewell.cmd`.
3. Чтобы начать локальное тестирование с нуля, запустите `start-firewell-clean.cmd`. Он сначала перемещает всю папку `data/` (SQLite, WAL, архивы матчей и резервные копии) в `local-reset-backups/data-before-reset-<дата>/`, затем создаёт пустую `data/` и запускает обычный сервер.
4. Закройте ранее открытый сервер до сброса. Ранее сохранённые токены браузера перестанут работать. При необходимости удалите данные сайта **только для** `http://localhost:3000` в настройках браузера и зарегистрируйте новые тестовые профили.
5. Откройте `http://localhost:3000`; для проверки запустите `npm test`.

**Внимание:** повторный запуск `start-firewell-clean.cmd` снова сбросит текущие тестовые аккаунты и матчи (с сохранением очередной локальной копии). Все данные удаляются из *активной локальной игры*, но сохраняются в резервной папке, откуда их можно вручную восстановить при остановленном сервере. `local-reset-backups/` не следует добавлять в Git, отправлять на Vercel или публиковать: там могут находиться личные данные, пароли в форме хешей и скрытые карты матчей.

Стартовая жизнь в обычной игре — **40 HP**, как и во всех текущих балансовых симуляциях. Движок включает «Неутомимость» и раздельные «Рвение»/«Пробивание» красных. Ранее созданные матчи сохраняют записанное здоровье; новые матчи начинают с 40 HP.
