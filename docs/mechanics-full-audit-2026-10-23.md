# Firewell CCG — актуальный аудит модульности и взаимодействий

**Дата:** 23 октября 2026. **Область:** ветка PR #41 \`codex/majestic-combat-only-20261023\`; игровые правила \`0.9.15-alpha\`. Аудит исходников и расширенных автоматических проверок; до зелёного CI и успешного деплоя не считать боевым релизом.

## Итог и границы

Архитектурно разделены **16 активных признаков** (\`src/mechanics/traits/*.ts\`), **14 модулей эффектов** (\`src/mechanics/effects/*.ts\`, из них 13 работающих, 1 заглушка \`ward\`) и **17 команд** в шести файлах \`src/mechanics/commands/\`. Реестр \`docs/mechanics-registry.json\` содержит 30 записей и проверяется тестами. Самостоятельность файлов не означает независимость от общей фазы/состояния: combat, zone/death queue, energy, statuses, rituals и UI задают семантику их пересечений.

### Каждый доступный признак

| Признак | Где реализован | Самостоятельность и взаимодействия |
|---|---|---|
| Страж (\`guard\`) | \`traits/guard.ts\`, \`commands/combat.ts\` | Отдельный предикат перехвата; должен сочетаться с Полётом/готовностью, подавляется Стазисом/Немотой |
| Полёт (\`flying\`) | \`traits/flying.ts\`, \`commands/combat.ts\` | Отдельная проверка допустимости перехвата; не означает запрета выбора целью Техники |
| Первый удар (\`firstStrike\`) | \`traits/firstStrike.ts\`, \`combat.ts\` | Ранний пакет боевого урона; проверяется с ответом, Щитом, Отравой |
| Пробивание (\`piercing\`) | \`traits/piercing.ts\`, \`combat.ts\` | Перенос излишка при перехвате; зависит от фактического Щита и здоровья перехватчика |
| Похищение жизни (\`lifesteal\`) | \`traits/lifesteal.ts\` | Лечение по фактическому урону и верхний предел HP; подавляется |
| Мгновенная атака (\`haste\`) | \`traits/haste.ts\`, \`commands/combat.ts\` | Атака в ход появления; не добавляет дополнительную атаку |
| Рвение (\`zeal\`) | \`traits/zeal.ts\`, \`commands/combat.ts\` | Атака в ход выхода только по Существам; с Мгновенной атакой работает через общий валидатор |
| Ещё удар! (\`extraAttacks\`) | \`traits/extraAttacks.ts\`, \`commands/combat.ts\` | Расширяет лимит самостоятельных атак; не заменяет Неутомимость |
| Неутомимость (\`untiring\`) | \`traits/untiring.ts\`, \`commands/combat.ts\` | Не истощает атакующего; число атак остаётся отдельным ограничением |
| Скрытность (\`stealth\`) | \`traits/stealth.ts\`, \`commands/combat.ts\` | Запрещает цель **атаки**, но не защищает от обычных техник/массового урона |
| Отрава при попадании (\`poisonHit\`) | \`traits/poisonHit.ts\`, \`combat.ts\`, \`statuses.ts\` | При положительном боевом уроне накладывает периодический урон; Щит может предотвратить попадание, Стазис останавливает тики |
| Щит (\`shield\`) | \`traits/shield.ts\`, \`combat.ts\` | Работает через отдельный расходуемый счётчик \`Permanent.shield\`; не только через печатный trait |
| Величественный (\`majestic\`) | \`traits/majestic.ts\`, эффекты, зоны, ритуалы, UI | Нельзя вручную выбрать целью прицельной техники/способности, вытеснить или принести в Жертву. **Можно атаковать Существом, наносить массовый и случайный урон, накладывать эффекты успешного попадания** |
| Не может атаковать (\`cannotAttack\`) | \`traits/cannotAttack.ts\`, \`commands/combat.ts\` | Существующий предикат читает печатное значение напрямую; подавление Немотой/Стазисом для отрицательного запрета сейчас НЕ симметрично с \`readTrait\`. Нужна отдельная норма, менять без утверждения нельзя |
| Жертва (\`sacrifice\`) | \`traits/sacrifice.ts\`, \`ritual.ts\` | Ритуальное участие через флаг перманента, требования цвета, готовности статусов и защиты Величественного; ритуал/награда — общие операции |
| Аура атаки (\`auraAttack\`) | \`traits/auraAttack.ts\`, \`combat.ts\` | Учитывается при вычислении боевой атаки; подавление источника выключает ауру |

### Каждый зарегистрированный эффект

| Эффект | Канал | Состояние и зависимости |
|---|---|---|
| \`bind\` | Technique | Работает; прицельный, нельзя выбрать Величественного |
| \`cleanse\` | Technique | Работает; дружественный прицельный, нельзя выбрать Величественного |
| \`silence\` | Technique | Работает; прицельный, нельзя выбрать Величественного |
| \`ward\` | Technique | **Не реализован**, зарегистрированный модуль всегда бросает RuleError; на выпускаемых картах отсутствует |
| \`reanimate\` | Technique | Работает; выбор карты **из сброса** (не перманента на поле), вторая шанс/лимит зон |
| \`recoverCreature\` | Loyalty | Работает; перенос из сброса в руку, не направлен на перманент на поле |
| \`damageOpponent\` | Technique / Loyalty / Death | Работает; только здоровье Владетеля, не цель-Существо |
| \`damageController\` | Death | Работает; урон Владетелю собственного владельца |
| \`damageAllCreatures\` | Death | Работает; массово бьёт всех Существ, **включая Величественных** |
| \`draw\` | Entry / Technique / Loyalty | Работает; добор с лимитом доступных карт |
| \`healRuler\` | Entry / Technique / Loyalty | Работает; лечение Владетеля с ограничением |
| \`stunEnemy\` | Entry | Работает; прицельный контроль, Величественных исключает |
| \`stasisEnemy\` | Entry | Работает; прицельный контроль, Величественных исключает |
| \`summon\` | Entry / Loyalty | Работает; универсальные параметризованные токены, лимит вспомогательной зоны |

**Изменения от прежнего аудита:** исторические четыре именных призыва \`summonSkeleton\`, \`summonBonePair\`, \`summonSignature\`, \`raiseSacrifice\` уже удалены как отдельные рабочие обработчики, хотя старые документы могут их перечислять. Они заменены \`summon\`; в реестре их нет. Токены и ритуальные награды имеют отдельные канонические файлы в \`src/cards/tokens/\` и \`src/cards/rewards/\`.

### Событийные, зональные и фазовые механики, не являющиеся одним trait/effect

- **Вступление, Второй шанс, Последнее слово:** обработка через события Entry/Death, детерминированную очередь и реестр эффектов; при одновременной смерти учитывается активная сторона и ID.
- **Статусы Ошеломление/Стазис/Немота/Отрава:** состояние в \`Permanent\`, фазовая обработка в \`commands/setup.ts\`, \`turns.ts\`, \`statuses.ts\`, \`trait-registry.ts\`. \`stun\` ограничивает атаку, \`stasis\` действия и активные traits; \`silence\` свойства и предсмертные эффекты; яд не тикает под Стазисом.
- **Бой:** единый пакет \`combat.ts\`, четыре стадии подключаемых хуков; есть отдельные действия объявления, перехвата и разрешения. Уникальность объектов и лимит атак обрабатываются в модулях команд.
- **Ритуал/Жертва/Награда:** \`ritual.ts\` и \`commands/rituals.ts\`, общий RNG \`nextRandom\`, раздельные основная зона (8) и вспомогательная (4), отрицательные \`onDeath\` и наградные fallback пути.
- **Уникальность, Вытеснение, Легенды, Лояльность, Аура, Автооплата Владениями, Добор Владетеля, Муллиган, Сброс, Лимит мест:** реализованы межмодульно; ни одно название карты не должно включать специальный путь в \`core.ts\`.
- **Неутомимость и ограничение нескольких атак** — независимые ограничения, действующие одновременно.
- **Случайный урон по Существам** как самостоятельный \`effect.kind\` в текущем реестре отсутствует. **Правило допустимости** заранее зафиксировано: при автоматическом случайном выборе цели Величественный не исключается из пула; подключить будущий эффект через отдельный модуль и общую функцию урона. Автотест проверяет выбор в искусственном пуле, но НЕ утверждает, что играбельная карта со случайным уроном уже существует.

### Запланировано, но не реализовано

| Механика | Текущий статус / условие появления |
|---|---|
| Настоящий Оберег (\`ward\`) | Есть зарегистрированная заглушка; нужны определение эффекта и тесты |
| Предвидение | Нет полного runtime-обработчика/контракта/UI; только дорожная карта |
| Отклик Владения | Не реализован (события Владений и требования интерфейса требуют отдельного решения) |
| Детонация | Не реализована; надо определить цель/смерть/массовость |
| Рикошет | Не реализован; важна граница между ручной целью и автоматически выбранной следующей целью |
| Магомутация | Отдельный дизайн в \`docs/magomutation-design-not-implemented.md\`, механики на действующих картах пока нет |
| Случайное нанесение урона Существам | Нет самостоятельного зарегистрированного эффекта; правило взаимодействия с Величественным определено, реализация в будущем |
| \`Card.abilities[]\` | Может содержать текст неподдержанных будущих свойств. Реестр игнорирует их как активные механики; UI явно отмечает как неактивные. Не считать реализованным |

### Проверка комбинаций и оставшиеся риски

| Взаимодействие | Факт / проверка |
|---|---|
| Величественный + прицельный эффект (вражеский **и союзный**) | Блокируется сервером; UI не предлагает недопустимые цели; карта и оплата при ошибке откатываются |
| Величественный + атака Существа | Разрешена |
| Величественный + Отрава от положительного боевого урона | Разрешена; периодические тики сохраняются |
| Величественный + массовый урон всем | Действует без исключения |
| Величественный + случайный урон без ручного выбора | Должен действовать; проверено на примере детерминированного пула, специализированный эффект ещё не написан |
| Страж + Полёт + Стазис/Немота | Перехват по требованиям обеих механик, подавление статуса действует через \`ability\` |
| Первый удар + ответный удар + Щит | Очередность и фактический урон сохраняются; есть существующие PvP/alpha тесты |
| Похищение жизни + Щит | Исцеляет только за реально нанесённый урон |
| Отрава + Щит + Стазис | Щит поглощает урон; Стазис приостанавливает и силу, и длительность тиков |
| Ошеломление + Стазис + Немота | Фазовые поля отдельны, сброс при окончании хода; нужна дальнейшая нормативная матрица комбинаций |
| Жертва + Величественный | Не может быть выбрана в Ритуале, даже с флагом Жертвы |
| Жертва + последние слова + массовый урон | Работа через очередь гибели; покрывается ритуальными тестами |
| Уникальность + замена + ритуальная награда | Проверка вытеснения Величественного применяется также к замене одноимённой Уникальной; откат при попытке заменить и возможность оставить старый объект |
| Немота/Стазис + \`cannotAttack\` | **Открыто:** код \`isAttackProhibited\` читает \`card.cannotAttack\` напрямую; \`readTrait\` его подавляет. Не менять правило без решения |
| Стазис + Отрава в архивных правилах | Старый текст v0.9.12 расходится с более поздним решением v0.9.13: текущий движок ставит тики на паузу; нужна единая нормативная формулировка |
| Попытки всех сочетаний в 324-строчной архивной матрице | **Не подтверждены полностью.** Старые 324 сценария — перечень требований (включая открытые), не 324 зелёных программных теста |

**Архитектурные риски для будущего исправления:** часть \`traits\` — модули регистрации, но правила их применения всё ещё распределены по командам и зонам; некоторые effect-модули имеют лишние импорты; UI выбора целей всё ещё ручной по \`effect.kind\`; интерфейс при добавлении следующей механики требует обновления RU/EN. Совмещённый тест для всех 16 свойств и всех фаз нельзя заменить одной проверкой реестра. Массовый рефакторинг без миграционной стратегии способен повредить сохраняемые матчи.

## Нейтральная колода — шесть физических Величественных

- **«Страж архивов»**: 3 атаки / 5 здоровья, стоимость 4, Страж, добавлен **Величественный**; уже 2 копии в \`neutral/index.ts\`.
- **«Последний часовой»**: 3 атаки / 4 здоровья, стоимость 4, Последнее слово (1 урон Владетелю противника), добавлен **Величественный**; уже 2 копии.
- **«Свирус Жирникус»**: 6 атаки / 5 здоровья, стоимость 6, Пробивание, добавлен **Величественный**; 2 существующие копии. Это единственное Существо нейтральной стартовой колоды дороже 5 энергии.
- Итого **три разные карты, 6 физических копий**, стартовая колода по-прежнему 70 карт. ID, цена, атака, здоровье и старые эффекты не изменены. Баланс после баффа требует отдельного большого прогона/живого PvP, а не только зелёного CI.

**Неизменность сохранений:** поля новых существ уже поддерживаются \`Card.majestic\`. Изменение карты в каталоге НЕ переписывает карточные снимки в ранее запущенных матчах. Ранее созданные комнаты могут сохранять старые данные карт до начала следующей игры. Изменять их без миграции нельзя.
