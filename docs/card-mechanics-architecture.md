# Архитектура карт и эффектов Firewell CCG

## Принцип

- `src/core.ts` задаёт состояние матча, транзакционную обработку команды, проверки ревизии и игровые инварианты. В нём **нет** имён отдельных карт и токенов.
- `src/mechanics/zones.ts`, `combat.ts`, `energy.ts`, `turns.ts`, `death-queue.ts`, `events.ts` и аналогичные модули содержат общие игровые операции.
- `src/mechanics/effects/<kind>.ts` — **один универсальный эффект на файл**. Он регистрирует `kind` через `registerEffect`, использует общие операции, не импортирует каталог карт и не знает конкретных персонажей.
- `src/cards/<color>/<type>/<card>.ts` — параметры и способности карты; `src/cards/tokens/<token>.ts` — самостоятельное определение токена. `src/cards/tokens.ts` оставлен как обратносуместимый экспорт, без собственных определений.
- Все новые карты используют имеющиеся эффекты, например `onEntry: {kind:'summon',cards:[...]}`, `onDeath: {kind:'damageOpponent',amount:1}`. Нельзя вводить `summonSomeNamedCreature` в механиках: конкретные существа задаются полем `cards`.
- Комбинация «призвать определённые карты, затем запустить доступный Ритуал» существует как данные `{kind:'summon',cards:[...],completeRitual:true}` для способности Легенды. Это не отдельный обработчик под карту.
- Для **новой операции** сначала вводится общий модуль эффекта + тип в `effect-contracts.ts`, регистрация в `effects/index.ts`, тесты и запись в `docs/mechanics-registry.json`. При этом не меняется `core.ts`.

## Текущая граница полной автоматизации

Новая карта, добавленная отдельным `.ts`-файлом в папку `src/cards/<color>/<type>/`, автоматически регистрируется **как дополнительная карта для пользовательских колод** при `npm start`, `npm test` или `start-firewell.cmd`. Для ручной проверки предусмотрено `npm run cards:check`, для синхронизации — `npm run cards:sync`. Состав шести стандартных колод по 70 карт не меняется автоматически: включение новых карт в стартовый набор требует отдельного балансного решения. В Git следует коммитить как файл карты, так и обновлённый `index.ts`, если автоматическая синхронизация меняла его. Сервер не загружает произвольный JavaScript от игроков.

## Ограничения на сериализацию

Данные карт, эффектов и токенов должны содержать только сериализуемые значения, не исполняемые функции. Все команды проходят общую серверную валидацию. Побочные действия и вложенные эффекты должны проходить через бюджет операций и очередь событий, чтобы не допустить бесконечной рекурсии.
