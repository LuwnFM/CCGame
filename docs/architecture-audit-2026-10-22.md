# Проверка архитектуры Firewell CCG — 2026-10-22

## Выполненная миграция
- Все десять текущих типов призываемых токенов определены в отдельных файлах `src/cards/tokens/`.
- Шесть Легенд и два фиолетовых Существа с эффектами призыва теперь **импортируют** эти определения. Повторные карты призыва используют одну и ту же ссылку на шаблон.
- Пять наград ритуала `vt-ritual` вынесены в отдельные файлы `src/cards/rewards/`; техника содержит ссылки на готовые модули.
- Новые тесты проверяют ссылочную идентичность и запрещают встроенные определения токенов в файлах обычных карт.

## Проверка core.ts
`core.ts` содержит типы состояния/команд, `player`, `initialGame`, `openingGame`, `apply`, проверку ревизии, идемпотентности и бюджет эффектов. Конкретные названия карт и токенов там не используются. Основной боевой алгоритм уже находится в `src/mechanics/combat.ts`, обработчики карт — в `src/mechanics/effects/`, логика зон — в `zones.ts`.

**Остающиеся компромиссы:** `core.ts` пока содержит длинные контракты `Card`, `Permanent`, `Player` и `Game`; при росте проекта эти интерфейсы можно вынести в `src/model/` с type-only импортами. Не следует одновременно переносить типы и менять схему сохранения активных игр без отдельной миграции. Реестры эффектов и признаков требуют статической регистрации модулей; это обеспечивает воспроизводимость и безопасность команд.

## Остальные папки
- `src/cards/<цвет>/<тип>/`: отдельные файлы карт уже есть; добавление новых файлов поддерживает `scripts/sync-card-catalog.mjs`, но стандартные колоды изменяются только по решению балансировки.
- `src/cards/rewards/`: новые канонические определения пяти наград ритуала.
- `src/mechanics/traits/`: отдельные модули для каждого ключевого слова.
- `src/mechanics/effects/`: общие операции без зависимости от конкретных карт.
- `src/mechanics/commands/`: остаются отдельные обработчики команд фаз, проверяющие доступность действий.
- `src/bots/`: логика тестового соперника отдельна от движка.
- `web/`: пока монолитный `app.js` (~45 KB); следующий безопасный этап — выделить renderer карт, слой API и управление диалогами в ES-модули, сохраняя HTML/DOM и существующие browser-E2E проверки.
- `src/legacy/`: исторические файлы могут оставаться физически, хотя выбор старого движка уже отключён; удалять архивные файлы необходимо только после проверки всех импортов и тестов.

## Архитектурные инварианты
1. Карта декларирует эффекты как данные; сервер исполняет только зарегистрированные безопасные механики.
2. Новый токен редактируется в одном файле; разные карты используют его импорт.
3. Новый игровой эффект регистрируется универсальным обработчиком, а не по имени персонажа.
4. Сериализация игры содержит данные карт, а не исполняемый код.
5. Любой перенос `Card`/модулей UI делается отдельным PR, без смешивания с изменениями баланса.
