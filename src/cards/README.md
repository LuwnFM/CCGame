# Каталог карт Firewell CCG

Каждая карта находится в собственном файле `src/cards/<цвет>/<тип>/<имя>.ts`. В файле определяются ID, характеристики, стоимость, лор и **сериализуемые данные эффектов**; никакие исполняемые callback-функции в карточные данные не встраиваются.

## Призыв и ритуальные награды

- Токены определяются **только** в `src/cards/tokens/<токен>.ts`. Карты, призывающие токен, импортируют это определение и передают его универсальному эффекту `{kind:'summon',cards:[TOKEN]}`. Не копируйте параметры токенов внутрь других карточек.
- Пять наград «Призыва забытой реликвии» определены в `src/cards/rewards/`; техника `vt-ritual.ts` импортирует канонические награды.
- Эффекты вроде `summonSkeleton`, `summonBonePair`, `summonSignature` и `raiseSacrifice` удалены как специальные алиасы. Вместо них используется универсальный `summon` с составом призыва в файле карты.
- Изменение токена выполняется в одном файле; пользовательские колоды и стартовые наборы должны сохранять существующие публичные ID карт, если не предусмотрена миграция.

## Регистрация новой карты

1. Создайте один файл в `src/cards/<цвет>/<тип>/`.
2. Сошлитесь на уже зарегистрированные эффекты, признаки и канонические токены/награды; при необходимости добавьте новую **универсальную** механику в `src/mechanics/effects/`, а не обработчик имени карты.
3. Запустите `npm run cards:sync`, затем `npm test`. Синхронизация также выполняется перед `npm start`, `npm test` и Windows-запуском `start-firewell.cmd`.
4. Новые карты автоматически попадают в дополнительные карты для пользовательских колод. Изменение стартового набора и числа копий — отдельное решение в цветном `index.ts`: стандартные колоды не изменяются автоматически.
5. Зафиксируйте созданный файл и изменённый `index.ts` в Git.

## Границы движка

`src/core.ts` содержит сериализуемое состояние, транзакционную `apply`, ревизии, идемпотентность и ограничения. Правила отдельных механик находятся в `src/mechanics/`, а не в `core.ts`. Нельзя исполнять JavaScript, переданный клиентом или описанием карты.

Для дальнейшего аудита см. `docs/card-mechanics-architecture.md` и `docs/architecture-audit-2026-10-22.md`.
